astro-blog のコンテンツはすべてファイルです。バックアップや移行には理想的ですが、日々の運用には少し不便です。ナビゲーションの文言 1 つ変えるのに、エディタを開き、ファイルを探し、書式を壊さないよう気を遣う——astro-blog-admin はまさにそのために作られました。Cloudflare Pages / EdgeOne Pages 上で動く管理画面で、ログインすれば記事、ノート、サイト設定、画像ホスティングのすべてをブラウザから管理でき、ブログ本体は純粋な静的・データベースなしのままです。

## 静的ブログに管理画面が要る理由

### ファイルの利点は揺るがない

管理画面は「コンテンツ即ファイル」の基盤を変えません。書き込む文字はすべて、ブログのリポジトリへのコミットになります。記事は Markdown ファイル、設定は JSONC ファイル。いつか管理画面を使わなくなっても、ファイルはそのまま残り、ビルドは通常通り走ります。

### 日々の運用は楽であるべき

頻繁な操作は数クリックで済むべきです。記事を公開する、キャッチコピーを直す、カバーを差し替える、トップページに絞り込みを足す。それらをエディタとコマンドラインに押し戻せば、ブログは「更新が面倒」という理由で静かになっていきます。

## ログインとセキュリティ

ログインは GitHub（GitHub App の OAuth）で、入れるのはリポジトリの所有者だけ。未ログインでは管理入口はログインページへリダイレクトされ、適当な公開 URL は 404、未認可の API 呼び出しは拒否されます。独自のアカウント基盤を持たないので、漏れるパスワードデータベースも存在しません。

## 管理できるもの

- **記事**：5 言語版の一覧・新規作成・編集・削除、下書きと人気フラグ、言語版ごとの削除；
- **ノート**：日付変更、リネーム、下書きスイッチを 1 枚のカードで；
- **ページ設定**：トップページ、About、Apple サブスクリプション、サービスなど、すべての JSONC 設定のビジュアル編集（次回詳しく）；
- **画像ホスティング**：アップロードしてリンク取得、画像管理、公開アップロードページ；
- **公開**：すべての変更は GitHub API 経由でブログのリポジトリにコミットされ、ホスティングが自動で再ビルドして反映します。

## 2 つのプロジェクトの関係

両者は別々にデプロイされた 2 つのサイトです。ブログは静的サイト、管理画面はサーバー側を持つ SSR アプリ。管理画面はブログのビルド内部を知らず、リポジトリ内のファイル規約だけを知っています。ブログ側も管理画面の存在に依存しません。この疎結合により、どちら側も単独で置き換え・引っ越しができます。
