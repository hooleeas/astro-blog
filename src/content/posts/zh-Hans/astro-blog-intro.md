很多个人博客最后都败给了维护：数据库要备份，程序要升级，某天服务器到期，几年的文字一起消失。astro-blog 的出发点很朴素——**内容就是文件**。文章是 Markdown，随记是 Markdown，站点设置是 JSONC，全部躺在一个 Git 仓库里。仓库在，博客就在；想搬家，克隆下来重新构建一次即可。

它用 [Astro](https://astro.build) 构建，构建产物是纯静态文件，可以放在任何静态托管上：GitHub Pages、Cloudflare Pages、EdgeOne Pages，或者一台最普通的虚拟主机。

## 它由什么组成

### 内容即文件

`src/content/posts/` 按语言分目录存放文章，`src/content/notes/` 存放随记，`src/data/` 里的几个 JSONC 文件保存全站设置：站点信息、导航、关于页面、服务列表等。没有数据库，也没有运行时查询，构建时一切都被编译进静态页面。

### 纯静态生成

每次构建，Astro 把 Markdown 渲染成 HTML，把多语言内容分别生成各自的页面。访问速度只取决于托管平台的 CDN，安全性则天然简单——没有可被攻击的动态接口，页面就是文件本身。

### 五种语言

站点内置简体中文、繁体中文、英语、日语、韩语五种语言。每篇文章可以有五个版本，界面文案也全部按语言组织，读者切换语言时看到的不只是翻译过的标题，而是整站一致的语言环境。

## 设计语言

### 浮动胶囊导航

页面顶部是一条浮动的胶囊形导航，毛玻璃质感，当前页面用一个会滑动的小气泡标记。深色模式切换按钮是站点的标志符号 ◐，跟随系统也可以手动切换。

### 排版与留白

正文排版以阅读为先：合适的行高、克制的标题层级、代码块语法高亮。移动端单独打磨过间距，单篇文章在手机上去掉容器圆角、改用分割线，和桌面端保持同一种气质。

## 适合谁

- 想要一个**长期可控**的个人站点，不想被某个平台绑定的作者；
- 习惯用 Git 管理文件，愿意接受“发文章 = 提交文件”的工程师；
- 需要多语言读者支持的跨语言写作者。
