astro-blog 的内容全是文件，这对备份和迁移是好事，但对日常维护不完全是：改个导航文字要开编辑器、找文件、注意别写错格式。astro-blog-admin 就是为此而建的——一个跑在 Cloudflare Pages / EdgeOne Pages 上的管理后台，登录之后，文章、随记、站点设置、图床，全都能在浏览器里管，而博客本体依然保持纯静态、零数据库。

## 静态博客为什么需要后台

### 文件的优势不动摇

后台不改变“内容即文件”的根基。它写入的每一个字，最终都会变成博客仓库里的一次提交：文章是 Markdown 文件，设置是 JSONC 文件。哪天不用后台了，文件原样都在，博客照常构建。

### 日常维护要顺手

高频操作应该是点几下就完成的事：发一篇文章、改一句标语、换一张封面、给首页加一个筛选。让这些事回到编辑器和命令行里去做，博客很快就会因为“懒得更新”而长草。

## 登录与安全

后台用 GitHub 账号登录（GitHub App 的 OAuth 流程），只有仓库所有者本人能进。未登录时后台入口跳登录页，公开地址乱输是 404，接口未授权一律拒绝。它不自建账号体系，也就没有密码库可泄。

## 它能管什么

- **文章**：五种语言版本的列表、新建、编辑、删除，草稿与热门标记，语言版本可以单独删改；
- **随记**：改日期、改名、草稿开关，都在同一个卡片里；
- **页面设置**：主页、关于、Apple 订阅、服务等全部 JSONC 设置的可视化编辑（下一篇细聊）；
- **图床**：上传拿链接、图片管理、公开上传页；
- **发布**：所有修改经 GitHub API 提交回博客仓库，托管平台自动重新构建上线。

## 和博客的关系

两个项目是分开部署的两个站点：博客是静态站，后台是带服务端能力的 SSR 应用。后台不知道博客的构建细节，只认仓库里的文件约定；博客也不依赖后台存在。这种松耦合让任何一边都可以单独替换、单独搬家。
