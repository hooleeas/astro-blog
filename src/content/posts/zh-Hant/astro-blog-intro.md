很多個人部落格最後都敗給了維護：資料庫要備份，程式要升級，某天伺服器到期，幾年的文字一起消失。astro-blog 的出發點很樸素——**內容就是檔案**。文章是 Markdown，隨記是 Markdown，站點設定是 JSONC，全部躺在一個 Git 倉庫裡。倉庫在，部落格就在；想搬家，克隆下來重新建構一次即可。

它用 [Astro](https://astro.build) 建構，建構產物是純靜態檔案，可以放在任何靜態託管上：GitHub Pages、Cloudflare Pages、EdgeOne Pages，或者一台最普通的虛擬主機。

## 它由什麼組成

### 內容即檔案

`src/content/posts/` 按語言分目錄存放文章，`src/content/notes/` 存放隨記，`src/data/` 裡的幾個 JSONC 檔案保存全站設定：站點資訊、導航、關於頁面、服務列表等。沒有資料庫，也沒有執行時查詢，建構時一切都被編譯進靜態頁面。

### 純靜態生成

每次建構，Astro 把 Markdown 渲染成 HTML，把多語言內容分別生成各自的頁面。存取速度只取決於託管平台的 CDN，安全性則天然簡單——沒有可被攻擊的動態介面，頁面就是檔案本身。

### 五種語言

站點內建簡體中文、繁體中文、英語、日語、韓語五種語言。每篇文章可以有五個版本，介面文案也全部按語言組織，讀者切換語言時看到的不只是翻譯過的標題，而是整站一致的語言環境。

## 設計語言

### 浮動膠囊導航

頁面頂部是一條浮動的膠囊形導航，毛玻璃質感，目前頁面用一個會滑動的小氣泡標記。深色模式切換按鈕是站點的標誌符號 ◐，跟隨系統也可以手動切換。

### 排版與留白

正文排版以閱讀為先：合適的行高、克制的標題層級、程式碼區塊語法高亮。行動端單獨打磨過間距，單篇文章在手機上去掉容器圓角、改用分割線，和桌面端保持同一種氣質。

## 適合誰

- 想要一個**長期可控**的個人站點，不想被某個平台綁定的作者；
- 習慣用 Git 管理檔案，願意接受「發文章 = 提交檔案」的工程師；
- 需要多語言讀者支援的跨語言寫作者。
