astro-blog 的內容全是檔案，這對備份和遷移是好事，但對日常維護不完全是：改個導航文字要開編輯器、找檔案、注意別寫錯格式。astro-blog-admin 就是為此而建的——一個跑在 Cloudflare Pages / EdgeOne Pages 上的管理後台，登入之後，文章、隨記、站點設定、圖床，全都能在瀏覽器裡管，而部落格本體依然保持純靜態、零資料庫。

## 靜態部落格為什麼需要後台

### 檔案的優勢不動搖

後台不改變「內容即檔案」的根基。它寫入的每一個字，最終都會變成部落格倉庫裡的一次提交：文章是 Markdown 檔案，設定是 JSONC 檔案。哪天不用後台了，檔案原樣都在，部落格照常建構。

### 日常維護要順手

高頻操作應該是點幾下就完成的事：發一篇文章、改一句標語、換一張封面、給首頁加一個篩選。讓這些事回到編輯器和命令列裡去做，部落格很快就會因為「懶得更新」而長草。

## 登入與安全

後台用 GitHub 帳號登入（GitHub App 的 OAuth 流程），只有倉庫所有者本人能進。未登入時後台入口跳登入頁，公開地址亂輸是 404，介面未授權一律拒絕。它不自建帳號體系，也就沒有密碼庫可洩。

## 它能管什麼

- **文章**：五種語言版本的列表、新建、編輯、刪除，草稿與熱門標記，語言版本可以單獨刪改；
- **隨記**：改日期、改名、草稿開關，都在同一個卡片裡；
- **頁面設定**：主頁、關於、Apple 訂閱、服務等全部 JSONC 設定的可視化編輯（下一篇細聊）；
- **圖床**：上傳拿連結、圖片管理、公開上傳頁；
- **發布**：所有修改經 GitHub API 提交回部落格倉庫，託管平台自動重新建構上線。

## 和部落格的關係

兩個項目是分開部署的兩個站點：部落格是靜態站，後台是帶伺服器端能力的 SSR 應用。後台不知道部落格的建構細節，只認倉庫裡的檔案約定；部落格也不依賴後台存在。這種鬆耦合讓任何一邊都可以單獨替換、單獨搬家。
