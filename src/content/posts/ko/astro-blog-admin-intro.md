astro-blog의 콘텐츠는 전부 파일입니다. 백업과 이사에는 좋지만 일상적인 유지보수에는 전부가 좋지만은 않습니다. 내비게이션 문구 하나 바꾸자고 편집기를 열고, 파일을 찾고, 형식을 깨지 않으려 신경 써야 한다면 곤란합니다. astro-blog-admin은 바로 그 지점에서 만들어졌습니다——Cloudflare Pages / EdgeOne Pages 위에서 도는 관리 화면으로, 로그인하면 글, 노트, 사이트 설정, 이미지 호스팅까지 전부 브라우저에서 관리할 수 있고, 블로그 본체는 순수 정적·데이터베이스 없음으로 남습니다.

## 정적 블로그에 관리 화면이 필요한 이유

### 파일의 장점은 흔들리지 않는다

관리 화면은 "콘텐츠 즉 파일"이라는 토대를 바꾸지 않습니다. 써넣는 모든 글자는 결국 블로그 저장소의 커밋이 됩니다. 글은 Markdown 파일, 설정은 JSONC 파일. 언젠가 관리 화면을 쓰지 않게 되어도 파일은 그대로 남아 정상적으로 빌드됩니다.

### 일상 유지보수는 편해야 한다

자주 하는 일은 몇 번의 클릭으로 끝나야 합니다. 글 발행, 문구 수정, 커버 교체, 홈페이지 필터 추가. 이런 일을 편집기와 명령줄로 되돌려 보내면 블로그는 "업데이트가 귀찮아서" 조용해지기 쉽습니다.

## 로그인과 보안

로그인은 GitHub(GitHub App의 OAuth)로 이뤄지며, 저장소 소유자만 들어올 수 있습니다. 로그아웃 상태에서는 관리 입구가 로그인 페이지로 이동하고, 임의의 공개 주소는 404이며, 인증 없는 API 호출은 거부됩니다. 자체 계정 시스템을 만들지 않으니 유출될 비밀번호 데이터베이스도 없습니다.

## 관리할 수 있는 것

- **글**: 다섯 언어 버전의 목록·작성·편집·삭제, 초안과 인기 표시, 언어 버전별 삭제;
- **노트**: 날짜 변경, 이름 바꾸기, 초안 스위치를 한 장의 카드에서;
- **페이지 설정**: 홈페이지, 소개, Apple 구독, 서비스 등 모든 JSONC 설정의 시각적 편집(다음 글에서 자세히);
- **이미지 호스팅**: 업로드하고 링크 받기, 이미지 관리, 공개 업로드 페이지;
- **발행**: 모든 변경은 GitHub API를 통해 블로그 저장소에 커밋되고, 호스팅 플랫폼이 자동으로 다시 빌드해 반영합니다.

## 두 프로젝트의 관계

둘은 따로 배포된 두 개의 사이트입니다. 블로그는 정적 사이트, 관리 화면은 서버 측을 가진 SSR 앱입니다. 관리 화면은 블로그의 빌드 내부 구조를 모르고 저장소 안의 파일 규약만 압니다. 블로그 역시 관리 화면의 존재에 의존하지 않습니다. 이 느슨한 결합 덕분에 어느 쪽이든 따로 교체하거나 이사할 수 있습니다.
