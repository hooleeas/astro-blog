많은 개인 블로그는 결국 유지보수에 집니다. 데이터베이스는 백업해야 하고, 프로그램은 업그레이드해야 하며, 어느 날 서버가 만료되면 몇 년치 글이 함께 사라집니다. astro-blog의 출발점은 소박합니다——**콘텐츠는 곧 파일**입니다. 글은 Markdown, 노트는 Markdown, 사이트 설정은 JSONC, 전부가 하나의 Git 저장소 안에 있습니다. 저장소가 있으면 블로그가 있고, 이사는 클론해서 다시 빌드하면 끝입니다.

[Astro](https://astro.build)로 만들었고 빌드 결과물은 순수 정적 파일이라 GitHub Pages, Cloudflare Pages, EdgeOne Pages는 물론 가장 평범한 웹 호스팅에도 올릴 수 있습니다.

## 무엇으로 이루어졌나

### 콘텐츠 즉 파일

`src/content/posts/`는 언어별 폴더에 글을, `src/content/notes/`는 노트를, `src/data/`의 JSONC 파일 몇 개는 사이트 전체 설정(사이트 정보, 내비게이션, 소개 페이지, 서비스 목록)을 담습니다. 데이터베이스도 런타임 조회도 없이, 빌드 시점에 모든 것이 정적 페이지로 컴파일됩니다.

### 순수 정적 생성

빌드할 때마다 Astro가 Markdown을 HTML로 렌더링하고 언어별로 페이지를 생성합니다. 속도는 호스팅의 CDN에만 달려 있고, 보안은 자연히 단순합니다——공격할 동적 인터페이스가 없고, 페이지가 곧 파일 자체이기 때문입니다.

### 다섯 가지 언어

사이트에는 중국어 간체, 중국어 번체, 영어, 일본어, 한국어 다섯 언어가 내장되어 있습니다. 모든 글은 다섯 가지 버전을 가질 수 있고, 인터페이스 문구도 전부 언어별로 정리되어 있어 언어를 바꾸면 제목만 번역된 페이지가 아니라 사이트 전체가 일관된 언어 환경을 제공합니다.

## 디자인 언어

### 떠 있는 캡슐 내비게이션

페이지 위에는 프로스트 글래스 질감의 캡슐형 내비게이션이 떠 있고, 현재 페이지는 미끄러지듯 이동하는 작은 버블로 표시됩니다. 다크 모드 토글 버튼에는 사이트의 상징인 ◐ 기호가 쓰이며, 시스템을 따르거나 직접 전환할 수 있습니다.

### 타이포그래피와 여백

본문은 읽기를 최우선으로 조판했습니다. 편안한 행간, 절제된 제목 단계, 문법 강조가 적용된 코드 블록. 모바일 간격은 따로 다듬어, 휴대폰에서는 글 컨테이너의 둥근 모서리를 없애고 구분선으로 바꿔 데스크톱과 같은 분위기를 유지합니다.

## 이런 분께 맞습니다

- 플랫폼에 묶이지 않고 **장기적으로 직접 통제할 수 있는** 개인 사이트를 원하는 저자;
- Git으로 파일을 관리하는 데 익숙하고 "발행 = 파일 커밋"을 받아들일 수 있는 엔지니어;
- 여러 언어의 독자를 지원해야 하는 저자.

바로 쓸 수 있는 온라인 편집 경험을 원한다면 자매 프로젝트인 astro-blog-admin이 그 빈틈을 채웁니다. 다음 글에서는 이 블로그의 다국어가 어떻게 조직되는지 살펴봅니다.
